## When the hold is released

The first experiment should be deliberately boring at the assembly layer and aggressive at the observation layer.

### Phase 1 — discovery

Run:

```bash
python tools/assemble.py discover
```

Check:

- only `mike-axiom-mir` repos are eligible;
- every eligible repo is public;
- the collaboration platform is excluded;
- `axm-monolith` is excluded;
- no unexpected public repo is being pulled into the AXM identity set.

If an unexpected public repo appears, **add an exclusion before building**. Do not rely on memory.

### Phase 2 — exact plan

Run:

```bash
python tools/assemble.py plan > first-plan.json
```

Review the exact repository list and pinned SHAs.

The plan itself is evidence of the requested moment. Do not silently refresh it after review and pretend it is the same snapshot.

### Phase 3 — materialize

Only after the plan is accepted for the experiment:

```bash
python tools/assemble.py build \
  --output ../axm-monolith-builds/<timestamp-or-label> \
  --confirm-build
```

Expected generated structure:

```text
<output>/
  axm-stack.lock.json
  MONOLITH_MANIFEST.json
  INVENTORY.md
  modules/
    <repo-a>/
    <repo-b>/
    ...
```

### Phase 4 — first truth pass

Before inventing cross-stack magic, measure the boring facts:

- repository count;
- file count;
- total disk footprint;
- duplicate filenames and probable duplicate concepts;
- languages/runtimes;
- local run instructions found;
- tests found;
- obvious incompatible assumptions;
- module-level tested / inferred / blocked / unknown status;
- modules that cannot be exercised on the current hardware/environment.

### Phase 5 — capability map

Then ask:

- what capabilities are independently present?
- which modules already expose clean connection surfaces?
- which modules describe the same primitive differently?
- what can be composed without source modification?
- what needs an adapter?
- what looks connectable but is not yet evidenced?

### Phase 6 — return repairs upstream

The generated monolith is not a replacement development branch for every module.

When the assembly exposes a real source problem, fix/propose it in the owning source repo and later regenerate another monolith snapshot.

## Stop condition for v0

v0 is successful when one explicitly requested moment can be reproduced as a namespaced public-stack snapshot with:

- exact source SHAs;
- explicit exclusions;
- no private source inclusion;
- no source mutations;
- no filename flattening;
- an honest inventory of what assembled and what remains unknown.

Do not claim full-stack interoperability merely because v0 assembly succeeds.
